MythicMobs + MMOItems

RPG Abilities

Build enchants around progression, combat state, exact MythicMob targets, and deliberate multi-enchant synergies.

Mythic Skill Signals

MythicMobs skills can now emit a typed signal into abilities installed on a player's live equipment. This enables boss phases, class skills, quests, and dungeon scripts to orchestrate enchant combinations without inventing a fake attack or apply event.

# MythicMobs skill
RaidFinisher:
  Skills:
    - omniEnchantSignal{signal=raid_finisher;slots=HAND,OFF_HAND;source=raid_boss} @target

# OmniEnchant ability
ability:
  raid_finisher:
    type: LIGHTNING
    mode: MYTHIC_SIGNAL:raid_finisher
    damage:
      formula: "2+{level}*1.5"

Real Equipment

The bridge reads enchant ids and levels from hand, off-hand, and armor at dispatch time. A skill cannot forge detached enchant state.

Two Owner Paths

A player caster owns the scan. Otherwise, a targeted player owns it, which lets a MythicMob signal every player selected by its targeter.

Canonical Pipeline

Chance, soul cost, Mythic/RPG conditions, activation history, CHAIN effects, and redacted trace output remain active.

Bounded Casts

Nested signals stop at depth four. Signal and ability cycles are rejected for one synchronous root cast.

Aliases are omniSignal/omiSignal and SIGNAL:<id>. slots defaults to ALL; use HAND, OFF_HAND, HEAD, CHEST, LEGS, or FEET. Signal abilities receive omi_trigger: MYTHIC_SIGNAL, omi_signal, and omi_signal_source. Other plugins can cancel OmniEnchantSignalEvent before any item is scanned.

Equipped Item Toolkit

MythicMobs skills can inspect and mutate only the player's current equipment. The bridge never accepts a detached item variable as authority, and every enchant change goes through OmniEnchant slot, applicability, conflict, lore, and lifecycle validation.

TypeComponentsPurpose
MechanicsomniEnchantItem, omniItemDurability, omniItemSouls, omniCompactSlots, omniGiveEnchantBookQuest rewards, upgrades, repairs, soul economies, and gear preparation
ConditionsomniHasEnchant, omniEnchantCount, omniEmptyEnchantSlots, omniItemDurability, omniItemSoulsBranch skills from exact live equipped item state
 
UpgradeReward:
  Conditions:
    - omniEmptyEnchantSlots{amount=>0;slots=HAND} true
  Skills:
    - omniEnchantItem{id=ember_brand;level=1;mode=ADD;slot=HAND;clamp=true} @trigger
    - omniItemSouls{mode=ADD;amount=5;pool=PVE;slot=HAND} @trigger

Selectors are TRIGGER, HAND, OFF_HAND, HEAD, CHEST, LEGS, FEET, and condition/compaction-only ALL. Mutations are synchronous, cancellable through OmniEnchantMythicItemMutationEvent, and protected by a depth-four cycle guard. See Mythic Mechanics and Mythic Conditions for every parameter and failure rule.

Effect Target

effect-target chooses who receives a Mythic or native mechanic. It is separate from condition-target, so an ability can inspect an enemy while healing its caster.

ability:
  blood_rite:
    type: HEAL
    mode: ATTACK
    effect-target: CASTER
    rpg-conditions:
      - "LETHAL"
    amount:
      formula: "1+{level}*0.5"

EVENT_TARGET is the backward-compatible default. Use CASTER for self-heal, self-buff, and defensive procs.

Stateful Conditions

Mythic Progress

MYTHIC_KILLS:crypt_wraith:20:3600 requires 20 named MythicMob kills in the last hour.

Exact Target

TARGET_MYTHIC:crypt_wraith only passes while the current target is that active MythicMob.

Focused Combo

COMBO_HITS:3:5 requires three direct hits on the same target within five seconds.

Lethal Strike

LETHAL only passes when current damage depletes target health and absorption.

Ordered Synergy

ENCHANT_SEQUENCE:ember_brand>void_mark:12:SAME_TARGET:CONSUME rewards that exact one-target proc order once.

Shared Roll

BATCHED_CHANCE:convergence:30:2 gives two linked checks the same 30% result for five seconds.

TRIGGER:ATTACK and ITEM_SLOT:HAND can be combined with any of these. Unknown, malformed, unavailable, and invalid RPG conditions fail closed.

Activation Conditions

Use these gates on mode: CHAIN abilities. All state is isolated per player, retained only for the configured window, and hard bounded.

ConditionPurposeDefaults and limits
ENCHANT_SEQUENCE:a>b:12Ordered subsequence; unrelated procs may occur between required entries.2-8 entries, ANY, CONSUME, 1-3600 seconds
ENCHANT_SEQUENCE:a>b:12:SAME_TARGET:REUSABLEOrdered recipe where every entry belongs to the current target.ANY/SAME_TARGET; CONSUME/REUSABLE
ENCHANT_ACTIVATIONS:a:3:10:SAME_TARGETRequires a minimum number of one enchant's successful procs.1-128 activations, 1-3600 seconds
RECENT_ENCHANTS:a,b:12Legacy unordered presence check retained for compatibility.Reusable until the window expires

A consuming sequence is only committed after every non-random RPG gate, shared chance, and CHAIN soul admission succeeds. One ability may contain one consuming sequence; malformed or ambiguous recipes disable that ability at reload.

Convergence Example

Proc Ember Brand and then Void Mark on the same target within 12 seconds. These branches share one chance result, independently consume that completed recipe, and use bounded recursion to prevent loops.

ability:
  convergence_heal:
    type: HEAL
    mode: CHAIN
    effect-target: CASTER
    rpg-conditions:
      - "ENCHANT_SEQUENCE:ember_brand>void_mark:12:SAME_TARGET:CONSUME"
      - "BATCHED_CHANCE:convergence:30:2"
    amount:
      formula: "1+{level}*0.75"
  convergence_chill:
    type: FREEZE
    mode: CHAIN
    rpg-conditions:
      - "ENCHANT_SEQUENCE:ember_brand>void_mark:12:SAME_TARGET:CONSUME"
      - "BATCHED_CHANCE:convergence:30:2"
    ticks:
      formula: "20+{level}*10"

Chain Context and Diagnostics

MythicMobs skills can inspect omi_chain_depth, omi_chain_root_enchant, and omi_chain_source_enchant. Every underscore key also has a kebab-case alias. Root casts use depth 0; each nested CHAIN cast increments it.

Enable debug-skill-trace and run /sle debug skill to inspect RPG_CONDITION_REJECTED, CHAIN_CYCLE_BLOCKED, and CHAIN_DEPTH_LIMIT. Traces remain redacted: no player identity, NBT, mechanic parameters, or exception text is stored.

XP Repair

MENDING_REPAIR turns part of a positive XP gain into durability for the enchanted item. It works with XP from every normal PlayerExpChangeEvent, so mob rewards, mining, smelting, and configured server rewards follow one predictable rule.

mechanics:
  - type: MENDING_REPAIR
    mode: XP_GAIN
    chance: "17+{level}*2"
    cooldown: "20"
    repair-per-xp: "1+{level}*0.35"

Only one damaged Omni-enchanted item is repaired per XP event. Priority is main hand, off hand, helmet, chestplate, leggings, then boots. The mechanic spends only the XP required for the completed repair and never repairs beyond the item's damage. Use a cooldown to keep large XP bursts intentional. MENDING, REPAIR_WITH_XP, and XP_REPAIR are accepted aliases.

Soulbound Recovery

SOULBOUND protects only its enchanted item from a player's death drops and returns it after respawn. It never enables global keepInventory, so the rest of the death, dungeon, and economy loop remains intact.

mechanics:
  - type: SOULBOUND
    mode: DEATH
    chance: "100"
    uses: "{level}"

Positive uses are initialized on first recovery and then stored per enchant on the item. Each successful recovery consumes one charge; uses: "-1" is unlimited. If the respawn inventory is full, the returned item drops at the respawn location. KEEP_ON_DEATH, RECOVER_ITEM, and SOUL_BIND are accepted aliases.

Item-State Gates

RPG conditions can now inspect the exact item that owns the ability. This makes low-durability clutch effects and same-item enchant builds possible without depending on temporary player state.

rpg-conditions:
  - "ITEM_DURABILITY:<=25"
  - "ITEM_ENCHANTS:vitality,bulwark"

ITEM_DURABILITY compares remaining durability from 0 to 100 using <, <=, >, >=, or =. ITEM_ENCHANTS requires every listed OmniEnchant to be installed on the same item. Non-damageable items, malformed comparisons, absent enchants, and unknown condition names fail closed.

Reload Safely

Put one YAML definition in plugins/OmniEnchant/enchants/, add its ID to _index.txt, then run /sle reload. Verify a new ability through /sle debug skill before building a longer chain. Default YAML files are never overwritten, so merge a revised default definition into an existing server's customized file deliberately.
