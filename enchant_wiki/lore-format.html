Lore Format Guide

How to configure #enchantslots# for ordered MMOItems enchant slots, plus the legacy #omnienchant# block.

How It Works

OmniEnchant uses placeholder tokens in MMOItems lore-format to determine where enchant information belongs. In v3.0.7 the recommended path is the MMOItems stat ENCHANTSLOTS plus #enchantslots#, which behaves like a gem slot list: each applied OmniEnchant fills the first empty configured slot.

config.ymlPlaceholder configuration
# Where enchant lore appears in MMOItems lore format.
# Add this string to your MMOItems lore where you want enchants to show.
# If not found and no previous OmniEnchant block exists, fallback is TOP.
lore-placeholder: "#omnienchant#"

# Legacy tokens still accepted as aliases:
lore-placeholder-aliases:
  - "#slenchant#"
  - "#ominienchant#"

# Number of blank lines between enchant block and item base lore
lore-spacing: 0
!

v3.0.7 behavior: use #enchantslots# for the ordered slot model. It owns that exact insertion point even when a legacy #omnienchant# block also exists on the item.

Recommended Slot Setup

Add the OmniEnchant slot stat to an MMOItems item, then place #enchantslots# where those slots should render in lore-format.yml.

MMOItems/item/SWORD/my_sword.ymlItem stat
enchantslots:
  - "1"
  - "2"
  - "3"
MMOItems/lore-format.ymlLore placement
lore-format:
  - '&7&m                              '
  - '#item-stat#'
  - '#enchantslots#'                         # Ordered OmniEnchant slots
  - '#stat-gem#'
  - '#item-lore#'
i

Applying an OmniEnchant fills the first empty slot. The counter line, for example Enchant Slot: 0/3, is rendered inside this same #enchantslots# block. Removing an enchant leaves that slot empty; an administrator can run /sle compact slots to move filled slots upward. Vanilla enchants may render in the same lore block, but they do not occupy OmniEnchant slots.

plugins/OmniEnchant/settings/display.ymlSlot display format
display:
  detail-limit: 3          # Applies only to non-slot/combined lore
  slot-name-format: "&eEnchant Slot {slot}: {rarity_color}{name} {level_roman}"
  slot-empty-format: "&8Enchant Slot {slot}: Empty"
  slot-desc-format:
    - "&7| {desc}"
  show-empty-slots: true
  slot-counter-format: "&bEnchant Slot: &a{used}&7/&f{max}"
i

Slot lore does not auto-compact at detail-limit. Before compact mode, every occupied slot shows its configured name plus every slot-desc-format description line. After a member enables /sle compact, descriptions are removed and all enchant names are grouped and wrapped; ten enchants still show all ten names. Use /sle compact off to restore descriptions, or /sle compact auto to return to the default. The equivalent /sle show detail|compact|auto forms remain available.

i

Items with older overfilled NBT are clamped to their effective slot list when built, rendered, or activated. A 5-slot item stores, displays, and runs at most 5 OmniEnchants. Give an item 10 configured enchantslots if it is meant to hold 10 enchantments.

Legacy Combined Block

Place the #omnienchant# token anywhere in your MMOItems item/type lore format if you want one combined enchant block instead of ordered slots.

Method 1 — In MMOItems lore-format.yml

MMOItems/lore-format.ymlLegacy combined block
# Add the placeholder in your lore format template:
lore-format:
  - '&7&m                              '     # Separator
  - '#omnienchant#'                          # ← Enchant lore goes here
  - '&7&m                              '     # Separator
  - '#item-stat#'
  - '#stat-gem#'
  - '&7'
  - '#item-lore#'

Method 2 — In individual item YAML

MMOItems/item/SWORD/my_sword.ymlPer-item override
lore:
  - '&8&m                    '
  - '#omnienchant#'                 # Enchant block inserted here
  - '&8&m                    '
  - '&7Damage: &f{attack-damage}'
  - '&7Speed: &f{attack-speed}'
i

The placeholder string is case-insensitive and accepts harmless formatting/spacing around the token. It is consumed and replaced with rendered enchant lines. If the item has no enchants, the placeholder line is removed.

MMOItems Build Path

For reliable placement, let MMOItems carry the token from its lore-format into the build pipeline. OmniEnchant injects ordered slots through ENCHANTSLOTS/#enchantslots#, or a legacy combined block through SLENCHANT/#omnienchant#.

i

Why this matters: only the final lore synchronizer writes the rendered enchant block. The MMOItems stats supply NBT and capacity but no longer write a second temporary lore block, so #enchantslots# stays in-place without a duplicate at the top.

MMOItems/lore-format.ymlStable placement checklist
# 1. Put one token exactly where enchant lore should appear.
'#enchantslots#'   # Recommended ordered slot model
'#omnienchant#'    # Legacy combined block

# 2. Save MMOItems config and reload/rebuild the affected MMOItems.
# 3. Existing items generated without this token need rebuild for exact placement.

OmniModifier Placeholder

If you use OmniModifier (SLMMOStatsApply), there's a separate placeholder for modifier lore sections.

config.ymlModifier lore section
# OmniModifier (SLMMOStatsApply) interop
modifier-lore:
  placeholder: "#ominimodifier#"
  placeholder-aliases:
    - "#slmmostatsapply#"
    - "#ominimodifier#"
  prefix: "&8[&bMod&8] &7"

External Enchant Lore

OmniEnchant includes adapter support for rendering enchants from other plugins (EcoEnchants, AdvancedEnchant) within the unified lore block.

config.ymlExternal enchant display
# External enchant lore section (EcoEnchants/AdvancedEnchant adapters)
external-lore:
  enabled: true
  prefix: "&8[&dExt&8] &7"
i

External enchants are appended after OmniEnchant enchants in the lore block. They inherit the same placeholder positioning.

Lore Spacing

Control the gap between the enchant block and adjacent lore content.

config.yml
# Number of blank lines between enchant lore block and item base lore.
# Default: 0 (no gap), set to 1 for a single blank line separator.
lore-spacing: 0
