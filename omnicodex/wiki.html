01 / INITIALIZE

Cho archive
một nguồn sự thật.

Codex không tự đoán lore hoặc display name. Server owner khai báo những identity bền vững trong catalog; player chỉ thấy tiến trình, không thấy logic rối phía sau.

  1. 01

    Drop the jar

    Đặt OmniCodex-0.1.0.jar vào plugins/, khởi động server bằng Java 21.

  2. 02

    Author catalog

    Viết entry, bundle và milestone trong ba YAML file được tạo sẵn.

  3. 03

    Validate first

    Chạy /oc validate. Config sai không thay registry đang hoạt động.

  4. 04

    Reload safely

    Dùng /oc reload; progress cũ và reward đã claim không bị thu hồi.

02 / DISCOVERY ENGINE

Một identity.
Một discovery.

Event chỉ là tín hiệu. Identity canonical mới là thứ được lưu: không amount, không lore, không random stats. Cùng một item đi qua pickup và inventory scan vẫn chỉ unlock một lần.

Items

Vanilla pickup/craft/inventory và MMOItems identity qua type + ID reflection.

Mobs & bosses

Vanilla death và MythicMob death có dedupe entity UUID để không double-count.

Dungeons

03 / CATALOG AUTHORING

Admin viết luật.
Codex tính phần còn lại.

Bundle có thể union exact entries với selector. Hand-authored entries.yml luôn override generated entry cùng canonical key — thuận tiện để sync MMOItems rồi chỉnh tier, icon, display name theo lore server.

entries.yml
entries:
  dragon-blade:
    key: ITEM:MMOITEMS:SWORD:DRAGON_BLADE
    display-name: "Dragon Blade"
    icon: DIAMOND_SWORD
    category: weapons
    tier: S
    tags: [sword, dragon, tier-s]
01

Sync suggestions

/oc sync items hoặc /oc sync mobs ghi generated-entries.yml, không ghi đè config của owner.

02

Explicit metadata wins

Tier S là metadata catalog. Không cần phụ thuộc native tier API của MMOItems để selector chạy ổn định.

03

Validate before swap

Reference sai, bundle rỗng, threshold vượt giới hạn hoặc placeholder nguy hiểm đều bị chặn trước reload.

bundles.yml
bundles:
  tier-s-swords:
    completion: ALL
    selector:
      all:
        - field: type
          equals: SWORD
        - field: tags
          contains: tier-s
milestones.yml
milestones:
  items-50:
    scope: ITEM
    threshold: 50
    rewards:
      - id: title
        type: COMMAND
        value: "... {player} ..."

04 / SAFE REWARDS

Completion is permanent.
Delivery is careful.

Reward không bị “fire-and-forget”. Mỗi reward có key ổn định, state rõ ràng và một inbox để player tự claim lại khi inventory có chỗ hoặc optional provider online.

01PENDINGbundle/milestone crossed
→
02DELIVERINGper-player claim lock
→
03DELIVEREDimmutable claim time
↺RETRYABLEfull inventory / provider missing

Command

Chỉ template trong config được chạy; placeholder hợp lệ: player, uuid, bundle, milestone.

Items

Vanilla item kiểm tra capacity trước; MMOItem missing sẽ giữ reward retryable.

Permission

Permission reward dùng Vault provider nếu có; không có provider thì không đánh dấu claim sai.

06 / FAQ

Known boundaries,
stated plainly.

Config invalid thì sao?

Registry đang chạy được giữ nguyên. /oc validate và server log chỉ ra path bị lỗi, sau đó owner sửa rồi reload lại.

Item stack 64 có unlock 64 lần không?

Không. Đây là unique discovery. Một canonical entry chỉ được ghi một lần cho mỗi UUID.

Full inventory có mất reward không?

Không. Vanilla item reward được giữ retryable trong inbox; player mở lại /oc rewards sau khi có slot trống.

Folia, MySQL và quantity collection?

Chưa thuộc release target. Bản hiện tại verified cho Paper 1.21 / Java 21, SQLite và unique discovery.
